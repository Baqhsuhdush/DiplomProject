# UI Copy Style Guide (RU)

Короткие правила для текстов интерфейса Qadam: единый профессиональный тон, без разговорных и личных формулировок.

## 1) Тон и стиль

- Деловой, нейтральный, короткий.
- Фокус на действии и результате.
- Без жаргона и уменьшительно-разговорных слов.
- Без эмоциональных фраз в системных сообщениях.

## 2) Что использовать

- `Требуется авторизация` вместо `Сначала войдите`.
- `Отчет`, `аналитика`, `задание`, `раздел`, `параметры`.
- Четкие CTA: `Сохранить`, `Обновить`, `Сформировать план`, `Открыть`.

## 3) Что избегать

- Разговорные формулировки: `домашка`, `пока пусто`, `нажми`.
- Избыточно личные формулировки в описаниях продукта.
- Длинные пояснения в одну строку без структуры.

## 4) Формат сообщений

- Ошибка: коротко + причина + (опц.) действие.
  - Пример: `Не удалось загрузить отчет. Повторите запрос.`
- Успех: факт сохранения/выполнения.
  - Пример: `Параметры сохранены.`
- Пустое состояние: нейтрально и конкретно.
  - Пример: `Записи отсутствуют.`

## 5) Термины (единый словарь)

- `Roadmap` (не смешивать с `road map`, `роадмап`).
- `Панель администратора` / `административный раздел`.
- `Учебные задания` (вместо разговорных синонимов).
- `Цель`, `задача`, `статус`, `период`, `уведомления`.

## 6) Примеры “до/после”

- До: `Сводка по целям и задачам, завершения, тесты и домашки.`
- После: `Операционная аналитика по целям и задачам: завершения, тесты и учебные задания.`

- До: `Всё равно сгенерировать`
- После: `Сформировать базовый план`

- До: `У вашего аккаунта нет прав администратора.`
- После: `Недостаточно прав для доступа к административному разделу.`

## 7) Чеклист перед merge

- Текст краткий и однозначный.
- Нет разговорных слов.
- CTA начинается с глагола.
- Термины соответствуют словарю выше.
- Ошибки и пустые состояния оформлены по шаблону.
